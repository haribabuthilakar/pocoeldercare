<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client HTTP Payload → Server DTO | Inbound JSON is validated against strict Zod schemas before reaching business logic. |
| Third-Party Webhook Request → System | Inbound webhooks from Razorpay/Exotel are validated via HMAC-SHA256 signatures before processing. |
| Multi-Role Authorization Boundary | Staff operations are gated by pure capability checks against the active UserRole set. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-SC | Tampering | npm dependencies (zod, zod-to-json-schema) | high | mitigate | Locked dependency versions and schema type-checking. |
| T-01-06 | Tampering | packages/business-rules/src/auth/webhooks.ts | critical | mitigate | Timing-safe buffer comparison in HMAC-SHA256 signature verification preventing webhook spoofing (D-116). |
| T-01-07 | Elevation of Privilege | packages/business-rules/src/auth/capabilities.ts | high | mitigate | Strict role-to-capability matrix evaluation preventing privilege escalation when staff hold multiple roles (D-65, AUTH-02). |
| T-01-08 | Repudiation | packages/validation/src/common/formats.ts | medium | mitigate | Strict Indian phone, ABHA ID, and PIN code regex validation preventing malformed or invalid national identities (D-68). |
</threat_model>
