  <action>
    1. Implement `TicketsService` in `apps/api/src/modules/tickets/tickets.service.ts`:
       - `createTicket(dto)`: Creates Ticket for household, calculates SLA response and delivery due dates using `calculateSlaDeadlines` from `@poco/business-rules`, assigns household's Care Officer, sets initial status `OPEN` (`TCKT-01`, `SLA-01`).
       - `triageToServiceRequests(ticketId, items: { serviceCatalogVersionId, notes }[], opsUserId)`: Creates 1 to N child `ServiceRequest` records, transitions ticket to `ASSIGNED` or `IN_PROGRESS` (`TCKT-02`, `D-22`).
       - `recalculateRollupStatus(ticketId)`: Gathers child service request statuses, executes `calculateTicketRollupStatus` from `@poco/business-rules`, updates Ticket status (handling ambiguous states by transitioning to `WAITING_OPS_UPDATE`) (`TCKT-04`, `TCKT-06`).
       - `resolveWaitingOpsUpdate(ticketId, resolutionAction, opsUserId)`: Allows Ops Executives in Admin Portal to resolve ambiguous state and set definitive status (`TCKT-07`).
    2. Implement `ServiceRequestsService` in `apps/api/src/modules/tickets/service-requests.service.ts`:
       - `transitionStatus(serviceRequestId, newStatus, actor)`: Executes `transitionServiceRequest` pure state machine (`PENDING -> ACCEPTED -> IN_TRANSIT -> ON_SITE -> IN_PROGRESS -> COMPLETED`) (`TCKT-03`).
       - Triggers parent ticket status rollup recalculation after every state transition.
    3. Implement `TicketsController` (`/api/admin/v1/tickets`):
       - `GET /api/admin/v1/tickets`: High-density operations queues (`PENDING_TRIAGE`, `WAITING_OPS_UPDATE`, `AT_RISK`, `BREACHED`).
       - `POST /api/admin/v1/tickets/:id/triage`: Triages ticket into child service requests.
       - `PATCH /api/admin/v1/tickets/:id/resolve-ops`: Resolves `WAITING_OPS_UPDATE` ticket.
  </action>
