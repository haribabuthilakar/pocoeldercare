  <action>
    1. Implement `BillingService` in `apps/api/src/modules/billing/billing.service.ts`:
       - `processBillingForService(serviceRequestId)`: Runs in a Prisma `$transaction`. Evaluates `evaluateBillingAction` from `@poco/business-rules` (BILL-01..05, D-20):
         * Step 1: Decrement available `QuotaUsage` against active subscription package quotas.
         * Step 2: Auto-debit `HouseholdWallet`, allowing negative balance overdraft if emergency flag is present. Creates immutable `WalletTransaction` audit entry with integer paise.
         * Step 3: If non-emergency and insufficient funds, set service request status to `PENDING` / `PENDING_APPROVAL` and emit notification.
       - `createTopUpOrder(householdId, amountPaise)`: Initiates Razorpay payment order via `@poco/integrations` Razorpay adapter (BILL-06).
       - `creditWalletFromWebhook(householdId, amountPaise, paymentId)`: Credits wallet balance and records `WALLET_CREDIT` transaction.
       - `generateInvoice(transactionId)`: Produces downloadable invoice metadata and PDF HTML representation (BILL-07).
    2. Implement `BillingController` (`/api/family/v1/billing` & `/api/admin/v1/billing`):
       - `GET /api/family/v1/billing/wallet`: Returns wallet balance, credit limit, and recent ledger transactions.
       - `POST /api/family/v1/billing/top-up`: Creates Razorpay top-up order.
       - `GET /api/family/v1/billing/invoices/:id`: Downloads transaction invoice.
    3. Write Vitest tests in `apps/api/test/billing.spec.ts`:
       - Quota decrement first when quota is available (BILL-02).
       - Wallet debit with sufficient balance (BILL-04).
       - Emergency overdraft allowing negative balance for emergency items (BILL-03).
       - Rejection / pending approval for non-emergency items with insufficient balance (BILL-05).
       - Wallet top-up and audit ledger immutability (BILL-01, BILL-06).
  </action>
